# 引き継ぎメモ(Handoff)

次の担当者・次プロジェクトへの引き継ぎ用メモ。プロジェクトの現状、これまでの
進め方の傾向、残課題をまとめる。

## 1. プロジェクト現状サマリ

- **本番稼働中**: https://mlit-links-akiya-ask.pages.dev/ (Cloudflare Pages)
- **構成**: 静的フロント(素の HTML/CSS/JS、ビルド工程なし)+ サーバ関数1本
  (`functions/api/search.js`、OpenAI 呼び出しとキー秘匿のみ)。
- **データ**: 別リポジトリ `MLIT-LINKS-akiya-pipeline` の Release 成果物
  (正規化済みデータセット)を `scripts/fetch-dataset.mjs` で取得・取り込み。
  本番は募集中 約7,500件。`data/akiya.json` は Git 管理外(ビルド時生成)。
- **検索**: AI検索(OpenAI で自然文→フィルタJSON)+ キーワード検索フォールバック。
  実際の絞り込みは常にブラウザ側 `filter.js`。
- **国際化**: 日本語/英語のUI切替(`assets/js/i18n.js`)。物件データは原文のまま。
- **テスト**: `node scripts/test.mjs`(51件、依存なし)。CI は未整備。

主要な意思決定の経緯:
- claude.ai アーティファクト経路を削除し、検索を「AI(サーバ経由)/キーワード」の2系統に簡素化。
- デプロイ先を Cloudflare Pages 一本に確定(GitHub Pages はサーバ関数を持てず AI検索不可のため不採用)。
- AI プロバイダを Anthropic から OpenAI(`gpt-4o-mini`)へ変更。

## 2. これまでの進め方の傾向(作業の好み)

次の担当者が同じ温度感で進められるよう、観測された進め方を記録する。

- **段階的に1トピックずつ**。区切りを明示し、合意してから次へ進む。大きな変更は
  独断で進めず、選択肢を提示して判断を仰ぐ。
- **判断前に「推奨」を求める**傾向。複数案を比較表で示し、理由付きで1案を推奨すると
  噛み合う(「オススメは?」と聞かれることが多い)。
- **仕組みの理解を重視**。実装前後に「どう動くか」を確認する質問が多い。
  コードの該当箇所(`ファイル:行`)を引きながら説明すると伝わりやすい。
- **定点観測レポートを好む**。「コードを実際に確認した事実のみ・推測は明記・
  変更はしない」形式のリポジトリ調査報告を節目で依頼する。このフォーマットは再利用価値が高い。
- **ドキュメント・構成図・テストを変更と同期**させる(README/docs/img/test を都度更新)。
- **コミットは小さく1論理変更**、日本語の簡潔なメッセージ。
- **実機確認を重視**(スクリーンショットや本番URLへの実リクエストで動作を確認してから完了とする)。
- **過剰実装を避ける**。割り切れる箇所は割り切り、制約はUIで明示する
  (例: 英語のキーワード検索は非対応 → 英語モードで注記表示)。

## 4. 次プロジェクト(データ更新)への引き継ぎ

- **データ更新手順**: パイプライン側で新しい年度版がリリースされたら、
  そのタグを渡すだけ。
  ```bash
  node scripts/fetch-dataset.mjs data-2026.1.0
  ```
  Cloudflare の Build command の引数を同様に変えれば本番も切替わる。
- **パイプライン本体はこのリポジトリには無い**。正規化ロジック(取得→構造化→
  AI分類)は `MLIT-LINKS-akiya-pipeline` 側。スキーマ変更があれば
  `scripts/import.mjs` の対応付け(`fromPipeline`)を追従させる必要がある。
- **必須シークレット**: 本番は `OPENAI_API_KEY`(Cloudflare 環境変数)。
  これが無いと `/api/search` が 500 を返し、フロントはキーワード検索に落ちる。
